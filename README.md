# Meet Attire

Chrome Manifest V3 extension that overlays professional upper-body attire onto your **Google Meet** camera feed. Processing is **100% local** — video never leaves your machine.

## Install (Load unpacked)

1. Open `chrome://extensions`
2. Enable **Developer mode** (top right)
3. Click **Load unpacked**
4. Select this folder:

```text
/workspace/meet-attire
```

(If you cloned the repo, select the cloned `meet-attire` directory that contains `manifest.json`.)

5. Open [Google Meet](https://meet.google.com), join or start a call, and turn on your camera.
6. Use the floating **"Change attire?"** panel (bottom-right) to pick an outfit or **Off / Original**.

### After clone — restore icons and PNG overlays

```bash
git clone https://github.com/nparikh211/meet-attire.git
cd meet-attire
bash scripts/decode_binary_assets.sh
```

Then Load unpacked → the cloned folder. SVG attire overlays ship as plain files; the content-script **bootstrap** loads gzipped JS from `content/b64/*.js.gz.b64` automatically (no decode needed for inject/UI). Decode restores icons + optional PNG attire for a polished UI.

The Load-unpacked folder on this box (`/workspace/meet-attire`) already has everything decoded.

### One-liner

```bash
git clone https://github.com/nparikh211/meet-attire.git && cd meet-attire && bash scripts/decode_binary_assets.sh && echo "Load unpacked → $(pwd)"
```

## Architecture

1. **`manifest.json` (MV3)** — content script on `https://meet.google.com/*`, `web_accessible_resources` for inject + attire assets. Minimal permissions (`storage` + Meet host).
2. **`content/content.js` (bootstrap)** — runs at `document_start`. Fetches `content/b64/inject.js.gz.b64` + `content/b64/content.ui.js.gz.b64`, gunzips via `DecompressionStream`, injects the page-world patch as a `<script>`, then `eval`s the UI in the content-script world.
3. **`content/inject.js` (page world)** — patches `navigator.mediaDevices.getUserMedia` early. Video tracks are replaced with a `canvas.captureStream` that composites clothing; audio is passed through unchanged. On any failure, Meet gets the **original** stream (fail-open).
4. **`content/content.ui.js`** — floating shadow-DOM panel ("Change attire?"), thumbnails, Off; bridges via `window.postMessage` with source `MEET_ATTIRE_EXT` and token `meet-attire-v1`.
5. **Processor** — prefers Chrome's built-in `FaceDetector` to place a torso box under the face; falls back to a center-upper heuristic. Clothing overlays are drawn with soft edges at ~24 fps (`requestVideoFrameCallback` when available).
6. **`assets/attire/`** — SVG overlays (+ PNG generated by `scripts/generate_assets.py`).

```text
meet-attire/
├── manifest.json
├── README.md
├── .gitignore
├── content/
│   ├── content.js          # bootstrap (loads gz.b64)
│   ├── content.ui.js       # panel UI (also shipped as b64/content.ui.js.gz.b64)
│   ├── inject.js           # getUserMedia patch (also as b64/inject.js.gz.b64)
│   └── b64/                # gzip+base64 packages for bootstrap
├── assets/

```

## Privacy

- Camera frames are processed **only in your browser**.
- No analytics, no remote APIs, no uploads.
- Choice of attire is stored in `chrome.storage.local` on your profile.

## How to test

1. Load unpacked as above.
2. Open Meet → mute optional → enable camera.
3. Confirm the panel appears and each option changes your self-view / what others see.
4. Click **Off / Original** — feed should match your real clothing again.
5. If something breaks, the extension falls back to the raw camera so Meet still works.

## Known limits (client-side clothing overlay)

- This is a **2D sprite overlay**, not 3D garment simulation or generative try-on. Sleeves, wrinkles, and lighting will not match a real shirt perfectly.
- FaceDetector coverage varies by Chrome version/OS; without it, placement uses a geometric heuristic (works best when you are centered and framed mid-chest up).
- Rapid motion, extreme angles, multiple people, or unusual framing can misalign the overlay.
- Meet UI updates or alternate camera paths may require adjusting the inject timing.
- Background effects / Meet "appearance" filters can interact oddly with an already-composited stream.

## Replacing assets

1. Drop new transparent PNGs/SVGs into `assets/attire/` (same filenames), **or**
2. Edit colors/shapes in `scripts/generate_assets.py` and run:

```bash
python3 scripts/generate_assets.py
```

3. If you change `inject.js` / `content.ui.js`, refresh the gzip sidecars:

```bash
python3 -c 'import gzip,base64,pathlib
for n in ["inject.js","content.ui.js"]:
 d=pathlib.Path("content")/n
 g=gzip.compress(d.read_bytes(),compresslevel=9,mtime=0)
 (pathlib.Path("content/b64")/f"{n}.gz.b64").write_text(base64.b64encode(g).decode()+"\n")'
```

4. Refresh the extension on `chrome://extensions` (reload button).

Thumbnail files live under `assets/attire/thumbs/` and should stay ~96×96 for the panel.

## Development notes

- Messaging token: `MEET_ATTIRE_EXT` / `meet-attire-v1` (ignore unrelated `postMessage` traffic).
- Panel uses **shadow DOM** so Meet's CSS does not restyle it.
- To debug: Meet tab → DevTools → Console; look for `[Meet Attire]` warnings from the page world.
- Full local push (after `gh auth login`): `bash scripts/push_to_github.sh`
